# Open Gaps

This is the single home for real gaps and short resolutions. Record a known defect/blocker promptly. Update the same row as it is fixed; do not maintain separate critical/non-critical/resolved copies or copy the full issue into every phase. Historical narrative/future-tense wording is not an open product gap.

| Gap / severity | Owner / next action | Status | Evidence / concise resolution |
| --- | --- | --- | --- |
| None currently recorded | None | None | Fresh ledger |

Statuses: Open, Resolved, Closed, Reclassified non-critical, None. Critical gaps must be fixed or correctly reclassified with evidence before their owning gate passes. No open gap may point to already-completed work as its next action. Correct a stale status in the current phase when valid resolution proof exists; return to an owning phase only when substantive repair/proof is missing. Retain short resolutions needed to avoid repeating work, with evidence pointers, not a growing event diary. No placeholder `Pending` gap rows after Phase 0.
